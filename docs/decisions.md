# Решения

## 2026-09-13 — Исходники ЛК и несколько OAuth-аккаунтов

- Веб-стек, ранее хранившийся только на VPS, размещён в `hosting/` этого репозитория.
- Повторная авторизация обновляет `(provider, subject)`; несколько разных внешних ID сохраняются отдельно.
- У Директа используется настоящий ID из `login.yandex.ru/info`, доступный без login-скоупов. Синтетический ID на основе пользователя ЛК больше не применяется.
- Подписанный OAuth state фиксирует пользователя ЛК и ожидаемый аккаунт между шагами; при смене сессии или аккаунта подключение прерывается.
- Перенос чужой строки подключения между пользователями ЛК запрещён.
- Состав аккаунтов облачного MCP обновляется при запросе; производная SQLite очищается от отключённых аккаунтов без замены API-ключа.
- Шлюз v0.9.0 использует исправленный `mcp-core`: срок токенов в секундах, собственная переменная ключа пакета. Общий кеш направлен в SQLite пользователя.

## 2026-09-13 — Подключение одним кликом

Кнопки сразу открывают OAuth: выбор аккаунта выполняется у провайдера.
Яндекс получает `force_confirm=yes`, Google — `prompt=select_account`.
Промежуточная форма и обязательный ввод почты отсутствуют.
Старые адреса `/app/connect/{yandex|google}` перенаправляют на OAuth.
